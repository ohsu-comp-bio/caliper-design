# What g3t Already Supports

Use cases in increasing order of complexity, some details on limitations and untested parts of the use cases.

## File Transfer into OHSU External-Facing Bucket

### Description
Users can *iteratively* transfer files on an out-of-network existing machine into an external OHSU bucket. This corresponds to Elizabeth 

### First Submission
Most important part here is we're only committing file manifest data, no FHIR metadata, and we use `--step transfer` flag when pushing.

```sh
# admin side
g3t collaborators approve -a -w /programs/<program_name>/project/<project_name> user@example.com

# developer side
g3t init program-example_project
g3t add file.txt
g3t commit
g3t push --step transfer
```

### Adding subsequent files
```sh
g3t add *.bam
g3t commit -m "add new bams"
g3t push —-step transfer
```

### Modifying existing files
Need to specify push `--overwrite` flag
```sh
g3t add existing.txt
g3t commit -m "update existing file"
g3t push —-step transfer --overwrite
```

## Upload local files to Populate the CALIPER Explorer

### First Submission
Same as above but creating FHIR metadata with `g3t meta init` and pushing the whole thing with `g3t push`.

```sh
# admin side
g3t collaborators approve -a -w /programs/<program_name>/project/<project_name> user@example.com

# developer side
g3t init program-example_project
g3t add file.txt
g3t meta init
g3t commit -m "add initial file"
g3t push --step transfer
```

### Adding subsequent files
Need to add `META/` that is regenerated by meta init
```sh
g3t add *.bam    # stages manifest (MANIFEST/)
g3t meta init
git add META/    # stage FHIR metadata (META/)
g3t push
```

### Modifying existing files

Same as adding files above except `g3t push --overwrite` to overwrite existing DVC records with your changes


## Upload FHIR metadata

## Users can *iteratively* upload local files and see basic file metadata populate in the Explorer.
    - **First submission**: `g3t collaborators approve` [admin side] → `init aced-myproject` → `add file.txt --patient patient_1` → **`meta init`** → `commit` → **`push`**
    - **Add new files**: `g3t add new_file.txt` → `g3t meta init` → `git add META/` → `g3t commit -am "add new file"` → `g3t push`
    - **Modify existing file**: same as above but `g3t push **—overwrite**`
  
## Users can upload remote files and see their basic metadata populated in the Explorer
    - **First submission**: same as above, but
- Existing: user can upload metadata pre-generated And see those changes in a Tabular format on the Explorer page
